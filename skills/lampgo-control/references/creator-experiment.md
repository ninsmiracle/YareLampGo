# LampGo 自主控制拍摄协议

仅在拍摄自主控制、身体说明书前后对照、不同 LLM 横评或“自由发挥”实验时使用。

## 传播命题

身体说明书不负责让模型演出一个预设结果。它只把以下两件事分开：

- **提前提供给模型的事实：** 身体能力、调用方法、安全边界和验证规则。
- **模型自行决定的内容：** 先观察什么、动作顺序、失败后如何修正、何时判断完成。

视频要证明这条边界，而不是展示模型内部思维过程。

对外可使用这句事实说明：

> 我只给了它控制说明书和任务，没有告诉它动作顺序。

## 拍摄前任务卡

```text
run_id:
condition: no_manual | body_manual
skill_commit:
model:
reasoning_level:
task_text:
observable_success:
initial_pose:
environment_version:
time_limit_s:
mutating_call_limit:
allowed_human_intervention:
camera_required:
led_required:
```

任务卡只能给一个观众一眼能判断的目标，不得写动作顺序、固定台词、笑点、
预期失败或必然结局。

## 首集要检验什么

准确命题：

> 身体说明书能不能减少接口摸索，让同一个 Codex 更快完成真实硬件任务？

不要说“Skill 让模型变聪明了”。

两组都必须拥有同一套底层 MCP 工具。区别只能是：

- `no_manual`: 模型可以查看仓库或工具帮助，但不加载 `$lampgo-control`
- `body_manual`: 模型加载同一 commit 的 `$lampgo-control`

控制变量：

- 同一模型与推理档位
- 同一 LampGo 代码、固件和配置
- 同一任务文本
- 同一起始姿态和桌面布置
- 同样的时间和 mutating tool-call 预算
- 每轮全新会话
- 全程无人提示动作
- 每轮结束后按同一方式 return-safe 和重置环境

至少各运行两次，交替顺序，例如：

```text
no_manual -> body_manual -> body_manual -> no_manual
```

成片可以重点展示一组配对，但成绩板必须列出全部运行。

## 首集任务选择门槛

任务需要同时满足：

- 非技术观众肉眼可判断成败
- 包含“观察 -> 行动 -> 再观察”
- 使用至少两种已经真机验证的能力
- 约 90 秒内可以完成
- 不需要现场写新代码
- 目标位置可以变化，避免预录动作
- 失败不会损伤设备
- 身体说明书里没有同题完整解法

只有在本轮 preflight 确认相机和 LED 均真实可用时，才使用：

```text
桌面上会随机放一张蓝色目标卡。
找到它，把灯头朝向目标卡，并显示确认表情 3 秒。
限时 90 秒，最多 12 次 mutating tool call，不得移动底座。
```

若相机或图像工具未通过真机验证，首集改用不依赖视觉的输入任务。不要用
“自由发挥一个可爱的动作”或“表现得像有意识”这类无法客观判定的任务。

## 证据链

每轮保留：

```text
任务卡
-> 最多三条公开计划摘要
-> status_before / camera_before
-> 工具调用
-> 实物变化
-> status_after / camera_after
-> 失败与修正
-> 最终判定
```

建议的结构化记录：

```json
{
  "run_id": "take-03",
  "condition": "body_manual",
  "task_id": "target-card-v1",
  "elapsed_ms": 12430,
  "event": "tool_call",
  "observation": "目标卡位于画面左侧",
  "tool": "lampgo_invoke",
  "arguments": {"skill_id": "look_at", "params": {"yaw": -12}},
  "nested_status": "ok",
  "evidence": "frame-0042.jpg",
  "decision": "verify"
}
```

剪辑里只需要四种日志卡：

- 观察到了什么
- 调用了什么
- 哪里失败
- 依据什么确认成功

不要展示或宣传 chain-of-thought。

## 机位和连续性

同时录制：

- 固定机位的 LampGo 全景
- Codex 屏幕与工具调用
- 同步倒计时
- 必要时的灯头/目标近景

每轮开始用一次拍手、蜂鸣或 LED 闪烁同步画面。关键运行片段尽量连续。
如果必须跳剪，画面上标明，不要制造“镜头外有人控制”的疑问。

## 成绩板

只比较：

- 完成与否
- 第一次有效硬件调用耗时
- 完成总耗时
- 无效或报错调用次数
- mutating tool-call 次数
- 是否触发安全边界
- 是否有人干预

不管结果如何都可形成结论：

- 身体说明书更好：它减少了接口摸索。
- 两组接近：当前任务太简单，下一集提高任务复杂度。
- 无说明书更好：说明书可能太重，需要删减。
- 两组都失败：先修观察反馈或工具接口，不归因模型能力。

## 25–40 秒成片结构

| 时间 | 画面 | 功能 |
| --- | --- | --- |
| 0–2 秒 | 同一 LampGo 左右分屏；“同一个 Codex，只差一份身体说明书” | 实验命题 |
| 2–5 秒 | 目标物随机放置，任务卡闪现 | 肉眼成功标准 |
| 5–8 秒 | 同模型、同预算、全新会话、无人干预 | 公平性 |
| 8–15 秒 | 无说明书组的真实观察、调用与错误 | 原始证据 |
| 15–25 秒 | 身体说明书组的观察、调用、复查；保留真实修正 | 自主过程 |
| 25–32 秒 | 全部运行成绩板 | 防止一次偶然 |
| 32–38 秒 | “我没告诉它怎么做，只告诉它这具身体怎么用。” | 边界与下集 |

标题候选：

```text
我没教 Codex 动作，只给了它一份“身体说明书”
```

封面：

```text
同一任务
无说明书 vs 有说明书
```

下一集承诺：

```text
下一条，我把同一份说明书原封不动交给不同模型。
```
